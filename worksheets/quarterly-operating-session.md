# Run the quarterly operating session

Run the one-to-two-hour leadership session that closes the last Sprint, picks the next one, and keeps your hybrid org's living document current — in four fixed steps.

The quarterly operating session is the meeting that turns one Sprint into a rhythm. Same agenda every quarter, same room, booked on the calendar before the year starts. You do four things in order: review the Sprint that just ran at the outcome level, re-rank the Constraint Backlog, commit the next Sprint, and update the Hybrid Accountability Chart. The output is a specific next-quarter commitment and an updated chart — made before the session closes, not "we'll circle back."

**Before you start:** Bring two inputs into the room — the previous Sprint's outcome statement and Compounding Scorecard (from Deliver and Compound), and the Constraint Backlog re-ranked at the end of the last Sprint. Bring the leadership team, including the constraint owner the Hybrid Accountability Chart names. Without the scorecard and the backlog, the session has nothing to decide from.

Copy this page and fill it in live during the session — one block per step, ending with the committed Sprint and the updated chart.

---

## Step 1: Review the previous Sprint at the outcome level

Determine whether the constraint actually moved and whether the workflow is permanent or needs another Sprint — the outcome question, not a status update.

1. Read the **Sprint outcome statement** from Deliver and the **retrospective findings** from Compound into the room. Have the constraint owner the chart names report the result — not the builder, not a status dashboard.
2. Answer the outcome questions in numbers: **Did the constraint move? By how much? What changed in the cost your team quantified during Signal** (before → after)?

   | Field | Fill in |
   |---|---|
   | Constraint the Sprint targeted | |
   | Cost before (from Signal) | |
   | Cost after (measured in Deliver) | |
   | Delta | |
3. Answer the **one question that determines what happens next: is the workflow permanent, or does it need another Sprint?** Record the decision. This is not the place for a status update on the agent team's day-to-day — that conversation happens elsewhere, more often.

> **Meridian example.** Sprint 1 targeted the quoting bottleneck: Elena Ruiz the sole quoter, 3.8-day turnaround. Cost before: $558K/yr. Cost after: $112K/yr. Delta: $446K/yr. Decision: workflow is permanent — standard turnaround dropped to 4.2 hours and throughput doubled, so the quoting agent team stays and no second Sprint is needed on this constraint.

## Step 2: Update the Constraint Backlog

Re-rank the running inventory of constraints so the next Sprint is chosen from current reality, not last quarter's assumptions.

1. Pull the **re-ranked backlog from the Compound phase**. Walk each candidate and check three things: **still relevant? cost changed? new information?** This is the same re-rank move as the Compound chapter's `constraint-re-rank` — run that logic here; it is authored once, used at two cadences.
2. **Add** any new constraints that emerged during the quarter and **remove** any that were resolved as side effects of the last Sprint. Then re-sort by cost so the most expensive operational problem sits on top.

   | Constraint | Annual cost | Changed since last quarter? | Keep / add / remove |
   |---|---|---|---|
   | | | | |
   | | | | |
   | | | | |
3. Confirm the backlog is **ranked**, not just a list — it is the input to every quarterly conversation, so the order has to reflect today's reality.

> **Meridian example.** After Sprint 1 shipped, the backlog re-ranked: the CRM-ERP sync problem (HubSpot and JobBOSS conflicting records) rose to the top because it had been invisible while Elena was the sole quoter — Sprint 1 exposed it. Customer onboarding (11-day manual handoff across 3 systems) and scheduling visibility stayed queued below it.

## Step 3: Commit the next Sprint

Convert backlog priority into a named constraint, a named Human Orchestrator, a budget confirmation, and a start date — the team leaves with a specific commitment.

1. Pick the **top constraint** from the updated backlog. Write it as the one-page **Constraint Statement** from Signal — one validated constraint, stated precisely.
2. **Name the Human Orchestrator** — the leadership-team member who owns the Sprint's output and supervises the agent team doing the work. (If you run EOS, this is the Integrator role extended to the Sprint, not the whole company.)
3. **Confirm resources and set the start date** so nobody leaves the room with an open question.

> **Meridian example.** At the Q4 2026 session, Meridian committed the CRM-ERP sync Sprint. Constraint: HubSpot and JobBOSS holding conflicting records, ~$74K/yr. Human Orchestrator: Elena Ruiz, VP of Operations (her freed quoting capacity redirected to designing workflows). The team left the session knowing exactly what the next Sprint was about and who owned it.

## Step 4: Update the Hybrid Accountability Chart

Make permanent any HAC rows from the completed Sprint, remove what didn't work, and reset the Hybrid Org Today baseline so the living document stays current.

1. **Make permanent** any HAC rows from the completed Sprint that are staying — agent teams, their human supervisors, shifted handoffs. **Remove or revise** any row that didn't work.
2. **Note which roles have shifted** since last quarter: if an agent team's scope changed, or the Human Orchestrator's handoffs moved, record it. (If you run EOS, the HAC extends your existing Accountability Chart — same structure, agent teams and their human supervisors added as rows.)

   | Accountability / handoff | Owner (human) | Agent team & supervisor | Permanent / revised / removed |
   |---|---|---|---|
   | | | | |
   | | | | |
3. Declare this the **new Hybrid Org Today baseline**. Update the living document here, in the meeting, with the leadership team — not by a Notion-curator on a Thursday afternoon. That ownership in the room is the discipline that keeps the document from rotting.

> **Meridian example.** After the quoting Sprint, Meridian made the quoting agent team and its human supervisor permanent rows on the Hybrid Accountability Chart, and Elena's role shifted from sole quoter to constraint owner and workflow designer. By the end of Sprint 3 the chart had been updated each quarter — quoting, CRM-ERP sync, and onboarding all carried as named rows in the current Hybrid Org Today.

## Before you call it done

Hand this page to someone who wasn't in the room. They should be able to see what the last Sprint produced, what the next one is, and where the org stands — without coming back to ask. Check:

- [ ] Step 1 records a **before → after delta** and the explicit decision: workflow permanent, or another Sprint.
- [ ] The Constraint Backlog is **re-ranked**, with new constraints added and resolved ones removed — ordered by cost.
- [ ] The next Sprint is **committed**: a one-sentence constraint, a **named** Human Orchestrator, resources confirmed, and a start date.
- [ ] The Hybrid Accountability Chart is **updated in the room** — permanent rows kept, dead rows removed, shifted roles noted.
- [ ] The result is declared the **new Hybrid Org Today baseline**, current as of today.
- [ ] The session produced a **specific commitment and an updated chart** before it closed — not a "we'll circle back."

Carry the committed Sprint into kickoff and the updated chart into the Hybrid Org Today, the one-page living document the next session reviews.
