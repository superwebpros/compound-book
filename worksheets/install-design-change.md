# Install One Design Change

*Turn one Sprint's retrospective into a single structural change the next Sprint inherits — named, installed, and verified before the next Sprint begins.*

After every Sprint, the Human Orchestrator answers one question: *what one design change would make the next Sprint better?* The answer is one. This worksheet takes you from "everything the Sprint surfaced" to a single change card that is actually installed in the chart, workflow, or Source map — not a "lessons learned" list that never lands.

**Before you start, you need a completed Sprint retrospective** — the honest list of what ran thin, what cadence was wrong, what handoff broke, what input needed cleaning nobody scoped. You are picking *one* item from it, not closing all of them.

---

## Survey everything the Sprint surfaced

Scan all retrospective items — Source gaps, wrong cadences, broken handoffs, dirty inputs — before picking anything.

1. List every observation the Sprint produced, in one place, with no editing yet. Pull from the retrospective: the Source phase that ran too thin, the supervisor cadence that was wrong, the handoff that broke once, the input format that needed cleaning nobody scoped.
2. For each item, write one line: what it cost this Sprint (time, a bad output, a manual rescue, an adoption gap).
3. Resist installing anything yet. This step is inventory, not decision — a long list here is fine because you are about to cut it to one.

> **Meridian:** The Sprint surfaced several items — among them the Quote Research Agent picking the wrong historical comparable on jobs with unusual fabrication complexity, which Elena Ruiz had to correct by hand. Each surfaced item got a line before anyone argued about which one to install.

---

## Name the single change that will most improve the next Sprint

The discipline of one defeats the "lessons learned list" failure mode; it forces a real priority decision.

1. From the surveyed list, ask of each item: *if we installed only this, how much better is the next Sprint?* Rank by that answer, not by how easy each is to fix.
2. Pick the **one** item at the top. Write a single sentence naming the change. If you can't pick one, you haven't ranked by impact — go back to step 1.
3. Cross the rest off this worksheet. They are not lost — re-ranking the Signal Backlog is where they get reconsidered. Here, only one survives.

> **Meridian:** Out of everything surfaced, the one change named was: add fabrication complexity indicators (bend count, tolerance class, weld count, surface finish) as matching criteria in the Quote Research Agent. That single change would most improve the next Sprint's quote accuracy, so it won; the other items went back to the backlog.

---

## Write the four-field change card (What / Who / How you'll know / By date)

Makes the change specific and testable; any blank field signals the change is too vague to install.

1. Fill in all four fields below. A blank field means the change isn't specific enough to install — resolve it now, not under next-Sprint pressure.

| Field | Fill in |
|---|---|
| **What** the change is | |
| **Who** installs it | |
| **How you'll know** it's working | |
| **By date** it's installed | |

2. Make "What" structural, not aspirational: a chart entry revised, a workflow step added, a guardrail tightened, a Source map updated, a prompt revised. "Improve quote accuracy" is not a change; "add four complexity indicators as agent matching criteria" is.
3. Make "How you'll know" a re-runnable test against real data, not a feeling. Name the actual records and the pass bar.

>
> | Field | Fill in |

> | **Who** installs it | Dave Kowalski provides the classification framework; Mark configures it in the agent |
> | **How you'll know** it's working | Re-run the 8 quotes Elena corrected last month — at least 7 of 8 produce the correct comparable job match |
> | **By date** it's installed | Before Sprint two kickoff |

---

## Install the change structurally before the next Sprint begins

An insight that doesn't change the design isn't worth recording — the change must land in the chart, workflow, or Source map.

1. Make the change in the actual artifact, not in a notes file. Open the Hybrid Accountability Chart, the workflow, the prompt, or the Source map and edit it so the next Sprint inherits the change as part of how the company now operates.
2. Confirm the person named in "Who" did the install, and that the supporting input exists. A change that depends on someone's expertise needs that expertise captured, not assumed.
3. Time-box it to the "By date." Compound is finished when this one change is installed — if it slips past next-Sprint kickoff, it isn't a change, it's a wish.

> **Meridian:** Dave Kowalski's thirty-one years of fabrication experience became the classification framework the agent uses when selecting historical matches; Mark configured it into the Quote Research Agent. The change landed in the agent's actual matching logic before Sprint two kickoff — not in a "lessons learned" doc.

---

## Verify the change using the "how you'll know" criterion

Closes the loop — confirms the change is working before Sprint two kicks off, not assumed.

1. Run the exact test you wrote in the "How you'll know" field. Use real data — last month's actual records, not a synthetic or cherry-picked example.
2. Compare the result to the pass bar you set. If it clears, the change is verified and Compound is done. If it doesn't, the change isn't installed correctly — fix it before the next Sprint, don't carry a broken change forward.
3. Record the verified result on the card so the next retrospective starts from confirmed fact, not memory.

> **Meridian:** Verification was re-running the eight quotes from the previous month where Elena had corrected the agent's match. With the complexity indicators installed, the test passed at the bar set — at least seven of eight produced the correct comparable — so the change was confirmed working before Sprint two, not assumed.

---

## Before you call it done

Run this test before the next Sprint begins:

- **Exactly one change was named.** Not a list, not three "quick wins" — one, chosen by impact on the next Sprint.
- **All four card fields are filled.** No blank What / Who / How you'll know / By date. A blank field means the change was too vague to install.
- **The change landed in a real artifact** — the chart, the workflow, the prompt, or the Source map — not in a notes file. The next Sprint inherits it structurally.
- **The "how you'll know" test was actually run against real data and passed.** The change is verified working, not assumed.

When all four are true, Compound is finished and the next Sprint inherits a company that operates one design change better than the last one.
