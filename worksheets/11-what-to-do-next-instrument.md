# First Sprint Planner

**Book Reference:** Chapter 11 — What to Do Next
**Instrument Type:** Synthesis / Action Plan

---

## Purpose

Every instrument in this book isolates one piece of the system. This one pulls them together. The First Sprint Planner takes your readiness score, your constraint, your team, and your chosen path — and reduces them to a single page you can act on Monday morning.

You have read the model. You understand the stages. Now write down what you are going to do.

---

## Part 1: Where Do You Stand?

Pull your AI Readiness Scorecard from Chapter 1. Look at your scores across the five dimensions.

**If you are mostly Red:**
Start with Signal. Name one constraint. Put a number on it. That is your entire first sprint goal. Do not try to run the full Sequence yet — get one clean Signal and build from there.

**If you are mixed Red and Yellow:**
Start with Signal and Source. Name the constraint, then map what you already know about it — the workflows, the people, the data. Two phases. One sprint.

**If you are mostly Yellow and Green:**
You are ready for a full sprint. Start with Signal, move through the Sequence. The instruments from Chapters 4 through 9 will guide each phase.

> **Action Step:** If you have not completed the AI Readiness Scorecard yet, go back to Chapter 1 and do it now. It takes ten minutes and tells you exactly where to start.

1. **What is the one operational problem that is costing you the most money or time right now?**

2. **What does it cost per year?**
   Write a number. Even a rough estimate works. If you cannot estimate it, that tells you something — your first sprint goal might be measuring it.

   _____________________________________________________________

3. **What would have to be true for it to be solved?**
   Write one sentence. This tells you whether the constraint is Sprint-solvable or whether something upstream needs to move first.

If you can answer all three, you have the seed of a Signal.

## Part 4: Pick Your Path

Two paths. Same framework. Same logic. The difference is speed and support, not methodology.

### Path A: Run It Yourself

Use the instruments from each chapter to guide the sprint:

- **Signal** (Chapter 4) — Define the constraint with precision
- **Source** (Chapter 5) — Map the knowledge around it
- **Design** (Chapter 6) — Architect the solution
- **Build** (Chapter 7) — Construct and test
- **Deliver** (Chapter 8) — Deploy and validate
- **Compound** (Chapter 9) — Extract the reusable pattern

Set the quarterly rhythm from Chapter 10 to make it repeatable. Each sprint sharpens your operating model. Each cycle compounds.

### Path B: Run It with Compound

- **Book a Clarity Call** (30 minutes, no cost) — an operator walks through your constraint with you and tells you whether it is Sprint-ready
- **Access the Compound Bench** — six coaching agents, one per sprint phase, that run the same logic as the worksheets in this book
- **Access the Skills Library** — twelve structured instruments that automate the analytical work behind each phase

The tools run the same methodology. They run it faster and more persistently than paper can.
