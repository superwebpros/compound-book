Map the Hybrid Split

Translate a finished Column A / Column B sort into a two-column picture of the redesigned seat: who manages, what the agent labors on.

You already split one role's weekly work into Column A (Human Intelligence: judgment that changes with context a machine can't observe) and Column B (Agent Intelligence: processing that follows rules a machine could learn). This worksheet turns that sort into the shape of the redesigned role — a single table where the human manages and the agent does the labor that follows rules. It's enough to see whether the new seat is viable and to hand off to the Sprint design work in the chapters ahead.

Before you start: Have the completed Column A / Column B sort for one role in front of you. The hybrid split is a re-presentation of that sort, not a fresh exercise — if the sort isn't done, do it first.

Fill in the two-column hybrid split, one row per accountability or task:

Human ManagesAgent Labors
_(judgment / direction the human keeps)__(rule-following work the agent owns)_

Then run the five steps below to make the split real.

Take the completed Column A / Column B sort

The sort is the raw material; the hybrid split translates it into a redesigned operating picture.

  1. Put the completed sort in front of you. Confirm every task the role spends real time on is already placed in Column A or Column B.
  2. Check for split tasks — work that contains both judgment and rule-following (for example, "managing scope change requests" splits into reading client politics and updating the change log). Confirm each part is sorted separately, not lumped into one column.
  3. If anything is still sitting in the wrong column or unsorted, fix it now. The hybrid split is only as honest as the sort underneath it.
Meridian example. Elena, CEO at Meridian Manufacturing, brought the completed sort for her client-success coordinator into the hybrid split. The sort came back 58% Column B: scheduling, status emails, update logs, and follow-up sequences in Column B; the three things that required knowing the client — reading when a relationship was at risk, deciding whether to escalate, and delivering hard news — in Column A.

Move Column B tasks into the 'Agent Labors' column

Names the specific work the agent will own, making the delegation explicit rather than implied.

  1. Copy each Column B task into the Agent Labors column, one row per task. Keep the wording concrete enough to delegate — name the actual activity, not a vague capability.
  2. State each as work an agent can own end to end ("sends weekly status update emails from templates"), not a fuzzy hand-wave ("helps with email").
  3. Confirm nothing from Column B got dropped on the way over. Every rule-following task the role does should appear here.
Meridian example. For the illustrative Project Coordinator, the Agent Labors column held: schedules client and internal meetings; sends weekly status update emails from templates; tracks deliverables against timelines and flags overdue items; writes meeting summaries and distributes action items; updates scope change logs (dates, costs, approvals); compiles lessons-learned documents from project notes.

Move Column A tasks into the 'Human Manages' column

Names the judgment and direction responsibilities the human retains, clarifying what the redesigned role actually requires.

  1. Copy each Column A task into the Human Manages column, one row per responsibility. Phrase each as the judgment being exercised, not the artifact produced.
  2. Where a task was split, capture the judgment half here (the change-log update went to Agent Labors; reading which changes to push back on stays here).
  3. Read down the column. This is what the redesigned role actually requires of a person — confirm it reads like work that needs a human, not leftovers.
Meridian example. For the illustrative Project Coordinator, the Human Manages column held: scope change requests (reads client politics, judges which changes to push back on); client-delivery coordination (navigates competing priorities, reads tension); timeline negotiations (decides what to concede, what to hold); client escalations (de-escalation, relationship repair, knowing when to involve leadership).

Add a quality-standard row for the human

Ensures the human's review responsibility over all agent output is explicit in the design — this is what prevents AI slop shipping under the role's name.

  1. Add one row to the Human Manages column: "Quality standard for all agent output — reviews before anything ships."
  2. Make it cover all Agent Labors, not one task. The human is the standard-holder for everything the agent produces under this role's name.
  3. Confirm the row is written as an active responsibility (reviews, approves, holds the line), not a passive hope that the agent gets it right.
Meridian example. The Project Coordinator's hybrid split adds the row "Quality standard for all agent output — reviews before anything ships" to Human Manages. That single row is what keeps the redesigned seat from quietly shipping unreviewed agent work under the coordinator's name.

Read the hybrid split as a role description

The completed table is the shape of the redesigned seat — enough to see whether it is viable and to hand off to Sprint design work.

  1. Read the whole table top to bottom as if it were a job description for the redesigned seat. Ask: is this a viable role a real person would want and could do well?
  2. Note that this two-column version is the starting point, not the final instrument. The Source chapter introduces the TML framework (Task / Management / Leadership), which sorts work into three categories; for now the two-column split is the right altitude.
  3. If multiple roles touch the same constraint, repeat the split for each, then compile one table — Role, Column B %, Loaded Cost, Annual Misallocation Cost — as the raw material the Sprint design work inherits.
Meridian example. Read as a role description, Elena's coordinator split shows a seat where the human manages the four relationship-and-judgment responsibilities plus the quality standard, while the agent labors on six rule-following tasks. That one split later became a single row of Meridian's Hybrid Accountability Chart — one function, mapped against the human-agent split, with a named supervisor on the Column B work.

Before you call it done

Hand the split to someone who didn't run the sort. They should be able to read it as the shape of the redesigned role — and know who owns what — without coming back to ask. Check:

  • [ ] The split started from a completed Column A / Column B sort, with split tasks separated.
  • [ ] Every Column B task appears in the Agent Labors column, worded concretely enough to delegate.
  • [ ] Every Column A task appears in the Human Manages column, worded as judgment retained.
  • [ ] A quality-standard row sits in Human Manages, covering all agent output, written as an active review responsibility.
  • [ ] The table reads as a viable role description — a seat a real person would want and could do well.

If any box is blank, the split isn't ready to hand to the Sprint design work — finish it here, not in Design.
